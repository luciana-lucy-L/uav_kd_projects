## 2. 命名规范

### 2.1 Run 目录

```
runs/<arm>_<capacity>/<YYYYMMDD_HHMMSS>/
```

| 字段 | 取值 |
|---|---|
| `arm` | `bc` / `traj_kd` / `ctrl_kd` / `joint_kd` / `feat_kd` |
| `capacity` | `l`（α=1.0）/ `m`（α=0.5）/ `s`（α=0.35） |

示例：`runs/traj_kd_s/20261102_143000/`

### 2.2 Run 目录内容（每次训练必须产出）

```
runs/<arm>_<capacity>/<timestamp>/
├── config.yaml            实际生效的完整配置（含所有默认值展开）
├── train.log
├── metrics.json           逐 epoch 的 train/val 指标
├── best_model.pt
├── last_model.pt
├── deploy_model.pt        剥离辅助头的部署检查点（TrajKD/JointKD 需要）
├── loss_curve.png
├── val_predictions/       预测 vs 教师的对比图
└── notes.md               本次运行的人工备注
```

### 2.3 数据集命名

`uav_kd_v2<序号>`，如 `uav_kd_v201`。v1 数据集（`uav_kd_v001/v002`）保留但**不用于 v2 训练**。

### 2.4 配置组织

```
configs/
├── base.yaml                     共享默认值（优化器、调度、日志）
├── arms/bc.yaml                  只描述"挂哪些头、用哪个 loss"
├── arms/traj_kd.yaml
├── arms/ctrl_kd.yaml
├── arms/joint_kd.yaml
├── arms/feat_kd.yaml
└── capacity/{l,m,s}.yaml         只描述 width_mult 与是否预训练
```

**运行方式**：`python -m kd_uav.train --arm traj_kd --capacity s`
**验收标准：换臂或换容量只改 YAML，不改代码。**

## 3. 统一训练设置

**所有臂必须一致，否则对照不成立。**

| 项 | 值 |
|---|---|
| 数据集 | 同一 `uav_kd_v2xx` |
| 划分 | 按 episode（见 `20_architecture/21_data_spec.md` §4.3） |
| 输入分辨率 | 224×224（BGR→RGB，归一化 [0,1]） |
| 序列窗口 T | 8（初值） |
| 优化器 | Adam，lr=1e-4，weight_decay=1e-4 |
| 调度 | cosine，3 epoch warmup |
| batch size | 32（序列样本，按显存调整） |
| epochs | 50（α<1.0 从头训练可能需上调，需记录） |
| dropout | 0.3 |
| 随机种子 | **每个配置跑 ≥ 2 个种子**，报告均值±标准差 |

⚠️ **种子数是 G2 判定的前提**：没有运行间方差就无法判断"臂之间的差异是否显著"。

### 超参数扫描

| 臂 | 扫描项 | 取值 | 何时 |
|---|---|---|---|
| TrajKD / JointKD | λ_traj | {0.1, 1.0, 5.0} | R2-W9 |
| CtrlKD / JointKD | H | {3, 5, 10} | 视 W7 结果定，非必须 |
| FeatKD | λ₁ 衰减 | 0.9→0.1 线性（跟随 Li & Zhao） | 固定 |

## 4. 评估协议

### 4.1 离线指标（全网格都做）

| 指标 | 定义 |
|---|---|
| Val loss | 各臂自身的验证损失（**跨臂不可直接比较**，损失定义不同） |
| **Ctrl MSE（分维）** | vx / vy / vz / yaw_rate —— **跨臂可比的主指标** |
| **yaw_rate std** | 预测的 yaw_rate 标准差，对照教师 0.340 |
| **转向帧分层指标** | 在 `is_turning=True` 子集上的 Ctrl MSE（避免直飞样本稀释） |
| Trajectory ATE | 仅 TrajKD / JointKD |
| Smoothness | 相邻帧控制指令差分的 L2 |
| 参数量 / 模型大小 | |
| 推理 FPS | 在部署硬件上实测 |

⚠️ **跨臂比较一律用 Ctrl MSE 和分层指标，不用 val loss。** 不同臂的 loss 定义不同，数值不可比——这是 v1 犯过的错（v001/v002 loss 被误比较）。

### 4.2 部署指标（约 8 个关键配置）

| 指标 | 定义 |
|---|---|
| **Success Rate (SR)** | 到达目标 0.5 m 内且无碰撞的任务比例 |
| **Collision Rate (CR)** | 发生碰撞的任务比例 |
| 完成时间 | 平均每任务耗时 |
| 轨迹误差 | 相对教师参考路径 |
| **部署期 yaw_rate std** | 与教师 0.340 对照 |
| **frac(\|yr\|>0.15)** | 与教师 17.7% 对照 |
| 实时 FPS | |

**每配置 N=10 次飞行**，固定路线与目标点序列，报告均值与成功/失败明细。

### 4.3 鲁棒性指标（C 轴）

| 指标 | 定义 |
|---|---|
| **相对退化率** | `(clean 指标 − 扰动指标) / clean 指标`，用于跨臂比较 |
| 扰动强度-性能曲线 | 每臂一条 |
| 崩溃阈值 | SR 跌破 50% 时的扰动强度 |

**为什么用相对退化率**：各臂 clean 性能不同，绝对值比较会被基线水平混淆。**鲁棒性结论必须基于相对退化。**

## 7. 公平对照的红线

违反任意一条，整组实验作废：

1. ✅ 所有臂使用**同一数据集、同一划分**
2. ✅ 所有臂使用**同一学生底座**（backbone + goal + LSTM），仅头与损失不同
3. ✅ 所有臂使用**同一部署接口**（图像 + 相对目标向量 → cmd_vel）
4. ✅ 所有臂使用**同一优化器/调度/epoch 数**（α<1.0 若需调整，则该容量下**所有臂**一起调整）
5. ✅ 部署评估使用**同一路线与目标点序列**
6. ✅ 跨臂比较只用可比指标（Ctrl MSE、分层指标、SR/CR、相对退化率）
7. ✅ 每配置 ≥ 2 个随机种子
