看图者 10 秒内必须得出：

> **经典教师内部有物理语义明确的模块边界，每一层都能吐出一种形式不同的知识；五个实验臂就是"换用哪一层知识来监督同一个学生"，除此之外一切都相同。**

## 4. 连接关系（本节是本图最容易画错的部分，请严格按数量执行）

### 4.0 三条铁律

1. **每个臂行有且只有一条入线箭头**，终止于该行"教师知识"格的**左缘**（不指向格内某个具体 chip）。
2. **全图只有一个合流点**，位于 JointKD 那条线上。除此之外任何两条线不得合并、不得共用箭头。
3. **箭头只表达"该臂的主监督信号"**；一个臂用到的其它知识成分（例如 TrajKD 也用动作 u）**只用 chip 表示，不画箭头**。

### 4.1 出线清单（按教师层看，共 6 条起点）

| 源 | 出线条数 | 每条去向 | 颜色 |
|---|---|---|---|
| P1 感知模块 | **1** | → R1 第 5 臂 | 青绿（灰化） |
| P2 规划模块 | **2** | ① → R2 TrajKD；② → 合流点 | 蓝 |
| P3 控制模块 | **2** | ① → R3 CtrlKD；② → 合流点 | 紫 |
| P4 最终动作 | **1** | → R5 BC | 深灰蓝 |

> P2 与 P3 各有**两条**出线，这是全图最常被漏画的地方：既要单独喂给自己那个臂，又要参与 JointKD 的合流。

### 4.2 入线清单（按臂行看，共 5 个箭头）

| 目标行 | 入线条数 | 来自 | 箭头颜色 |
|---|---|---|---|
| R1 第 5 臂 | **1** | P1 | 青绿（灰化） |
| R2 TrajKD | **1** | P2 | 蓝 |
| R3 CtrlKD | **1** | P3 | 紫 |
| R4 JointKD | **1** | 合流点（P2 蓝 + P3 紫汇成） | 合流后一段画成蓝紫双色或深靛 `#4B4BA8` |
| R5 BC | **1** | P4 | 深灰蓝 |

### 4.3 数量校验（画完先自查）

> **6 条起点 ／ 1 个合流点 ／ 5 个箭头**
> 若箭头数不等于 5，或存在任何一行没有箭头，即为错误。

### 4.4 其它线与对齐

| 项 | 要求 |
|---|---|
| 教师内部顺序线 | P1 → P2 → P3 → P4，深灰**实线**箭头 2.5 px，垂直向下穿过各板中心正下方 |
| 第 3 列内部 | `[统一底座]` → 头 chip，深灰实线细箭头，**五行画法完全一致** |
| 对齐 | P1 中心 ↔ R1 行中心；P2 ↔ R2；**P3 ↔ R3**；P4 ↔ R5。四块板等间距，五个数据行等高 |
| JointKD 的高度 | R4 位于 R3 与 R5 之间；蓝紫两股由上方斜行下来汇合，合流点画一个实心圆点 |

### 4.5 布线规则

- 所有教师 → 臂的线一律**虚线**；箭头为实心三角，终点与目标格左缘留 8–12 px 间隙
- 走线优先横平竖直，仅蓝紫两股汇入合流点时允许斜行
- **任何箭头不得被徽章、括号或标签遮挡**。若发生冲突，移动徽章/标签，**不得**移动或缩短箭头
- 中带内除箭头与其文字标签外不放任何元素

## 6. 风格层（可执行指令）

- **整体气质**：扁平化信息图，学术可用。**无阴影、无渐变、无透视灭点、无发光、无材质**
- **等轴测层板画法**：顶面为平行四边形，水平边与斜边长度比约 `3 : 1`，斜边与水平线夹角 **30°**；板厚 14–18 px，顶面下方接一条同宽深色侧带。**顶面用该层主色，侧带用主色加深 18%；四块板角度、尺寸、厚度画法一致**（P4 厚度为 1/3）。板面**不加排线阴影、不加手绘质感**
- **配色分工**：颜色只编码"教师的哪一层"，**不编码工作归属**。工作归属由**形状 + 底板**表达：教师＝立体板 + 灰蓝底板；本研究＝扁平圆角框 + 米白底板

  - 统一底座灰 `#E8E8E8` / 边框 `#BDBDBD` / 文字 `#6E6E6E`
- **chip 规格（五行统一）**：圆角胶囊，圆角半径为高度的一半；填充为该层主色 15% 透明度，边框为主色 1.5 px，文字为主色加深 20%；所有 chip 等高。**不得出现深色实心 chip**

## 7. 禁止项

1. **不要**给任何一个臂加 `Proposed Method` / `核心创新` / `Ours` 标记 —— 五个臂平权对照
2. **不要**写任何实验结果、性能评价或倾向性批注（如"不稳定"、"效果最好"）
3. **不要**标注文献归属（如"某某的工作"）—— 那属于相关工作章节
4. **不要**在控制模块板内写 `MPC`、`PID`、`LQR` 或任何控制器算法名称 —— 教师用的是 tracking controller，写 MPC 属于事实错误
5. **不要**在感知模块板内画传感器清单（LiDAR / 深度 / 全局地图）—— 那是传感器，不是感知模块的输出
6. **不要**画学生网络内部结构（卷积块、LSTM 展开、维度数）—— 第 3 列只用统一灰色胶囊代表
7. **不要**画容量 α 取值、扰动类型、训练网格、轮次（R2/R3）—— 那是三轴设计图
8. **不要**让五行的"学生通路"列出现任何差异（宽度、颜色、文字）
9. **不要**画装饰性图标（无人机、传感器图标等）
10. **不要**复现手绘稿的排线阴影、纸张纹理、手写体
11. **不要**出现 SelfRedWP、FeatKD、InfoNCE、Teach-and-Repeat 等已废弃方案字样
12. **不要**使用渐变、阴影、玻璃拟态、立体投影等装饰效果

## 10. 历史踩坑（**必须与 §1–§7 一起粘给生成模型**）

以下是前两次实际生成中出现过的错误，请在作图时特别规避：

1. **CtrlKD 行漏画入线**（连续两次出错）。紫色线从控制模块直接下折去了 JointKD，跳过 CtrlKD，导致该行的 `U 控制序列` chip 孤立无来源。**控制模块必须有两条出线。**
2. **JointKD 只收到单色线**。JointKD 的入线必须由蓝、紫两股汇合而成，能看出"两层知识合用"。
3. **橙色"唯一变量"徽章压在数据行上**，遮挡了该行的入线落点。徽章必须置于括号正上方、与表头行同高。
4. **控制模块板内被自行添加 `MPC / Controller` 方块** —— 事实错误，教师用的是 tracking controller。该板面必须留空。
5. **感知模块板内被自行添加传感器清单** —— 传感器不等于感知模块输出。该板内只画占据栅格。
6. **最终动作板未减薄，并被添加无人机图标** —— 该板厚度必须为其它板的 1/3，板面留空。
7. **BC 行的 `u 动作` chip 被画成深色实心**，与其它浅填充 chip 样式不一致。所有 chip 必须同一套样式。
8. **控制板与 CtrlKD 行未对齐**，视觉上偏向 JointKD。四组对齐关系必须严格执行。
