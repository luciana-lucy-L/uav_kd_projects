> 层级：输出层。**本文件是"给生成式 AI 画图的说明书"，不是图本身。**
> 用法：把 §1–§7 与 §10 整段粘给生成式 AI；出图后用 §8 逐条核对。**§10 必须一起粘。**
> 数据来源：`20_architecture/20_architecture.md` §2、§2.1、§2.2、§4（本图所有维度与命名以该文件为准）。
> 与其他图的边界：
> - 本图**不画**教师系统、不画五个臂的对照表 —— 那是 `实验臂对照.md`
> - 本图**不画**容量 α 的取值组合网格与扰动类型 —— 那是三轴设计图
> - `实验臂对照.md` 里第 3 列那个灰色胶囊 `RGB + Goal → MobileNetV2(α) → LSTM`，就是本图的压缩形态，两者命名必须一致

## 1. 主张（唯一结论）

看图者 10 秒内必须得出：

> **五个臂共用这一个底座；不同的臂只是挂载不同的头。部署时只带走控制类的头，轨迹头和感知头在训练结束后被丢弃；学生手里只有前视 RGB 和一个相对目标向量。**

图的说服力来自两条视觉线索：**主干只有一条**，以及**一条清晰的"部署边界"把头分成两组**。

## 4. 连接关系

### 4.0 两条铁律

1. **主干只有一条**。从输入到 LSTM，全图不得出现第二条并行主干或任何分叉（Goal Encoder 那一路是支路，必须汇回主轴）。
2. **四个头的入线画法完全相同**：都从 `h_t` 引出，同样的线型、线宽、长度处理。头与头之间**不得有任何连线**。

### 4.1 连接清单

| # | 从 → 到 | 线型 | 线上文字 |
|---|---|---|---|
| 1 | I1 → M1 | 深灰实线粗箭头 2.5 px | 无 |
| 2 | I2 → M3 | 深灰实线细箭头 1.5 px | 无 |
| 3 | M1 → M4 | 深灰实线粗箭头 2.5 px | `D(α)` |
| 4 | M3 → M4 | 深灰实线细箭头 1.5 px，自下方斜向上汇入 | `64` |
| 5 | M4 → M5 | 深灰实线粗箭头 2.5 px | 无 |
| 6 | M5 → 分叉点 | 深灰实线粗箭头 2.5 px | `h_t` |
| 7 | 分叉点 → Hd1 / Hd2 / Hd3 / Hd4 | 四条深灰实线细箭头 1.5 px，扇形分叉，**四条画法一致** | 无 |
| 8 | Hd1、Hd2 → 底部部署链左端 | 深灰实线细箭头，向下汇入 | 无 |
| 9 | 底部部署链内部四环节 | 深灰实线粗箭头 | 无 |

### 4.2 数量校验

> **主通路箭头 6 条（#1–#6）／头分叉箭头 4 条／部署汇入箭头 2 条／部署链箭头 3 条。**
> Hd3 与 Hd4 **不得**有任何指向底部部署链的箭头 —— 它们在部署时不存在。

### 4.3 对齐

- I1、M1、M4、M5 的垂直中心严格对齐在同一条水平主轴上
- I2、M3 位于主轴下方同一条辅助线上
- Hd1–Hd4 等高等宽、等间距垂直堆叠，四者左缘对齐
- DB1 部署边界线正好落在 Hd2 与 Hd3 的间隙正中

## 6. 风格层（可执行指令）

- **整体气质**：扁平化技术示意图。**无阴影、无渐变、无 3D、无发光、无材质**
- **配色策略（本图与其它图不同，务必遵守）**：全图以中性灰蓝为主，**只有两处允许出现彩色**——
  - **橙色 `#E1701C`**：只用于 Backbone 边框、容量轴徽章 M2、部署边界线 DB1、脚注 F1 的竖条。其它任何地方不得出现橙色

  - 其余一切（输入框、Goal Encoder、concat、LSTM、连接线、文字）一律用深灰蓝 `#5A6B7C` / 灰 `#9E9E9E` / 深灰黑 `#1A2A3A`

## 7. 禁止项

1. **不要**画教师系统、教师信号、蒸馏损失、五臂对照表 —— 那些是别的图
2. **不要**画 α 的三个取值如何组合成训练网格，**不要**画扰动类型 —— 那是三轴设计图
3. **不要**在输入端画深度图、点云、地图、位姿或教师轨迹的任何**有效**入线（它们只能出现在 I3 的灰色划除清单里）
4. **不要**只写其中一个分辨率 —— 必须同时写 `原始 480 × 640 × 3` 与 `网络输入 224 × 224`，并画出 resize 关系
5. **不要**把 Ctrl Head 与 CtrlSeq Head 画成同时部署于同一个臂 —— 图上不表达"同时"，只表达"这两个头都属于部署侧"，具体哪个臂挂哪个由右侧臂标签说明
6. **不要**画 loss 函数、损失公式、反向传播箭头、梯度符号。教师监督**只以子列 3 的虚线 chip 文字出现**，不得画成箭头、不得画出教师系统本身
7. **不要**画具体超参数（学习率、batch size、epoch）或通道数、卷积核尺寸
8. **不要**画循环箭头表示 LSTM 的时间递归，也不要把 LSTM 展开成时间链
9. **不要**出现 SelfRedWP、FeatKD、InfoNCE、red waypoint 等已废弃方案字样

## 10. 历史踩坑（**必须与 §1–§7 一起粘给生成模型**）

以下是本项目其它框架图生成时反复出现的错误类型，本图同样适用：

1. **自行添加未要求的元素**（传感器清单、算法名称、无人机图标、装饰插画）。凡 §3 未列出的元素一律不画。
2. **多条线被合并或漏画**。本图的四条头分叉线必须各自独立、画法一致；`h_t` 分叉点只有一个。
3. **标签/徽章压住箭头落点**。容量轴徽章 M2 必须贴在 Backbone 框的**上方外侧**，不得压在框内文字或任何箭头上。
4. **虚线/实线语义混用**。本图只有一种虚线用途：灰色虚线 = 仅训练期或待定；橙色虚线 = 部署边界。**前向数据流一律实线**，不得出现虚线箭头。
5. **配色蔓延**。橙色和绿色各自只允许出现在 §6 明确列出的位置；不要因为"好看"给 LSTM、concat、输入框上色。
6. **维度写错或漏写**。所有维度表达式必须逐字照抄 §3，不得自行简化为"feature"、"vector"之类。
