## 1. 主张（唯一结论）

看图者 10 秒内必须得出：

> **这项研究由三个正交的轴定义（知识层级 × 学生容量 × 输入扰动）；21 周被切成四轮螺旋，每轮末有一个决策门，前两轮完成即已构成一篇合格论文，最后一轮整轮可牺牲。**

面向的读者是**指导教授**：他必须能从图上直接读到 ——「压缩轴是他指派的题目」、「鲁棒性轴是实验室主轴」、「什么时候能看到什么交付物」、「哪里是最大风险、失败了怎么办」。

## 4. 连接关系

本图**不是流程图**，元素之间几乎没有箭头。只有以下三类连接：

| # | 关系 | 画法 |
|---|---|---|
| 1 | 决策门三角 → 其判据框 | 一条短的垂直细实线（1 px，深灰），三角在上、判据框在下 |
| 2 | 轮次泳道 → 其任务卡 | **不画连线**，靠左右边缘严格对齐表达归属 |
| 3 | C 轴卡片组 → A×B 网格 | **一条紫色点划线箭头**，从 C 轴区左缘指向 A×B 网格右缘，线上标注 `evaluated on every trained config  对每个训练好的配置施加` |

> 除上述三类外，全图不得出现任何其它箭头或连线。

**对齐要求（本图可读性的关键）：**
- 每个轮次泳道的左右边界必须与刻度轴上对应周次的格线**严格对齐**
- 任务卡宽度与其轮次泳道等宽、左右对齐
- 决策门三角的尖端落在对应周次格线的**右边界**上（W2 末即 W2 与 W3 的交界）
- 交付物阶梯的每一级左边界，与对应轮次的右边界对齐

## 5. 文字层

- 所有标题与徽章**英文在上、中文在下**；正文密集处允许中英混排在同一行（用 `｜` 分隔）
- 日期一律 `MM-DD` 格式；跨年处（W18 起）不额外标年份，靠轴两端的 `2026-09-07` / `2027-01-31` 界定
- 任务卡内每行以 `W<n>` 开头，周次编号加粗
- 判据框内 `✅` / `❌` 开头的两行必须对齐排版，视觉上形成"通过 / 不通过"的二分
- 数学符号（α、σ、λ、τ）一律斜体衬线体
- 最小字号在长边 5500 px 下不小于 22 px

## 10. 历史踩坑（**必须与 §1–§7 一起粘给生成模型**）

以下是本项目其它框架图生成时反复出现的错误，本图同样适用：

1. **自行添加未要求的元素**。凡 §3 未列出的元素一律不画（尤其不要加日历图标、进度百分比、人物插画）。
2. **自行修改数字**。周次、日期、编号、参数取值必须逐字照抄，模型不得"合理化"或补齐它认为缺失的项。
3. **标签压住其它元素**。徽章、判据框、警示条不得覆盖刻度轴、泳道边界或网格格线；冲突时移动标签而非压缩主体。
4. **对齐失守**。轮次泳道、任务卡、决策门、交付物阶梯四行必须共用同一套周次格线，横向严格对齐——这是本图最容易崩的地方。
5. **配色蔓延**。紫 / 橙 / 青绿三色只用于各自的轴与呼应的轮次；不要给刻度轴、任务卡正文、脚注上色。
6. **把可牺牲的部分画得同样醒目**。R4 与 W17 必须在视觉上明显弱于 R1–R3，否则风险控制的设计意图就丢了。
