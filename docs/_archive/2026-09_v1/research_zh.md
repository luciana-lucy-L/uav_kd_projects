## 1. 摘要

深度学习的最新进展显著提升了无人机自主导航能力。然而，许多基于视觉的导航模型仍依赖大型神经网络和大量算力，在轻量无人机平台上部署十分困难。相比之下，经典自主飞行系统通过精心设计的感知、规划与控制模块，能够提供可靠的导航性能，但通常需要复杂的系统架构和较高的计算成本。

本研究提出一个知识蒸馏（KD）框架，将导航能力从经典自主飞行系统迁移到轻量视觉无人机策略。与传统 KD（大型神经网络 → 小型神经网络）不同，这里的教师是一个完整的经典机器人自主飞行系统（CERLAB Autonomous Flight），而非神经网络。学生是一个轻量神经网络，在推理阶段仅使用单目前视相机图像作为输入。

我们提出 **JointKD**，一种双层蒸馏方法，同时向学生迁移规划层知识（来自教师规划器的未来轨迹）与执行层知识（来自教师控制器的控制序列）。轨迹监督作为辅助训练信号，将规划意图注入共享 backbone，而控制序列头则作为部署时的输出。BC、TrajKD、CtrlKD 作为消融实验，用以验证各组成部分的贡献。目标是在显著降低模型复杂度和部署成本的同时，保留导航能力。

## 2. 研究定位

### 2.1 创新点：以经典系统作为教师

| 类型 | 教师 | 学生 | 被蒸馏的知识 |
|---|---|---|---|
| 传统 KD | 大型神经网络 | 小型神经网络 | 软标签 / 特征 |
| 策略蒸馏 | 专家 RL 策略 | 学生策略 | 动作 / 策略 |
| **本研究** | **经典无人机自主飞行系统** | **轻量视觉策略** | **轨迹 + 控制** |

教师不是神经网络，而是一个完整的经典自主飞行流水线，由 感知 → 规划 → 控制 模块组成。被蒸馏的知识不是软分类 logits，而是结构化的规划输出（轨迹）和控制指令。

### 2.2 与行为克隆（BC）的区别

| | BC | 本研究 |
|---|---|---|
| 教师信号 | 最终动作标签 | 中间规划输出 + 控制 |
| 学到的内容 | 采取了什么动作 | 去哪里（轨迹）+ 如何移动（控制） |
| 规划结构 | 隐式 | 通过轨迹监督显式建模 |

纯 BC 只学习"观测 → 动作"的直接映射。本框架额外使用规划器的轨迹输出作为结构化监督，编码教师的导航意图，而不仅仅是其最终动作。

### 2.3 核心研究问题与提出的方法

我们提出 **JointKD**：一种双层知识蒸馏方法，同时将规划层知识（轨迹）与执行层知识（控制序列）从经典无人机自主飞行系统迁移到轻量前视视觉策略。

**设计理由：** 经典教师编码了两种本质不同的导航智能——规划器的空间意图（去哪里）与控制器的时序执行行为（如何移动）。只蒸馏其中一种会使学生对教师导航能力的理解不完整。JointKD 旨在同时捕获这两者。

> **核心问题：为什么联合蒸馏轨迹（规划）知识与控制序列（执行）知识，能比只蒸馏其中一种产生更强的轻量视觉策略？**

## 3. 总体框架

```
  ╔═══════════════════════════════════════════════════════════════╗
  ║             CERLAB 教师系统（Gazebo，运行时）                  ║
  ║   LiDAR · RGB-D · IMU · 里程计 · 地图                          ║
  ║                                                               ║
  ║   感知 ──▶ B样条 规划器 ──▶ 跟踪控制器                        ║
  ╚══════════════════════╤════════════════════════╤══════════════╝
                         │                        │
              τ_t：K=10 个机体系                U_t：H 步控制序列
              路点（规划器输出）              [u_t … u_{t+H}]（控制器输出）
                         │                        │
                ─────────────────────────────────────────
                         ↓  离线同步录制
  ┌──────────────────────────────────────────────────────────────┐
  │                    教师知识数据集                              │
  │                                                              │
  │    图像 I_t  │  轨迹 τ_t   │  控制序列 U_t              │
  │  (前视相机)   │  (规划器输出) │  (控制器输出)                │
  └───────────────────────────┬──────────────────────────────────┘
                              │  KD 监督标签
                  ════════════╪════════════════════════════════════
                  训练阶段    ↓
  ╔═════════════════════════════════════════════════════════════╗
  ║                  JointKD 学生网络                            ║
  ║                                                             ║
  ║     输入：仅前视相机图像 I_t                                 ║
  ║                       ↓                                     ║
  ║           MobileNetV2 Backbone（1280 维）                   ║
  ║                  ┌────┴────┐                                ║
  ║                  ↓         ↓                                ║
  ║   ┌──────────────────┐  ┌──────────────────────┐           ║
  ║   │    轨迹头         │  │    控制序列头         │           ║
  ║   │   τ_student       │  │  [u_t … u_{t+H}]    │           ║
  ║   │                  │  │                      │           ║
  ║   │  ▶ 仅训练使用     │  │  ▶ 训练 + 部署使用   │           ║
  ║   │  （辅助监督）      │  │  （receding horizon）│           ║
  ║   └────────┬─────────┘  └──────────┬───────────┘           ║
  ║            │                       │                        ║
  ║        L_traj（辅助）           L_ctrl_seq（主）             ║
  ╚════════════╪═══════════════════════╪════════════════════════╝
               └───────────┬───────────┘
                           ↓
         L = λ_traj · L_traj + λ_ctrl · L_ctrl_seq

         L_traj     = MSE(τ_student, τ_teacher)
         L_ctrl_seq = Σ_{k=0}^{H-1} w_k · MSE(u_pred(t+k), u_teacher(t+k))

                  ════════════════════════════════════
                  部署阶段（教师系统不运行）

              前视相机 I_t
                    ↓
          仅使用 MobileNetV2 + 控制序列头
                    ↓
         [u_t, u_{t+1}, …, u_{t+H}]
                    ↓  执行 u_t，下一帧重新预测
                 cmd_vel → 无人机
```

**消融实验：** BC、TrajKD、CtrlKD 分别隔离出 JointKD 的各个组成部分。

```
  ┌──────────┬───────────────────────────┬────────────────────────────┐
  │ 方法      │ 训练监督                  │ 部署输出                    │
  ├──────────┼───────────────────────────┼────────────────────────────┤
  │ BC       │ u_t（单步）                │ cmd_vel（单步）              │
  │ TrajKD   │ τ_t（辅助）+ u_t（主）     │ cmd_vel（单步）              │
  │ CtrlKD   │ U_t（H 步序列）            │ cmd_vel（receding horizon） │
  │ JointKD  │ τ_t（辅助）+ U_t（主）     │ cmd_vel（receding horizon） │
  └──────────┴───────────────────────────┴────────────────────────────┘
```

**关键原则：** 教师在数据采集时使用丰富的多传感器状态（LiDAR、地图、里程计）。学生在部署时仅使用前视相机图像。教师信号只作为 KD 监督标签使用——推理阶段学生永远无法获取。

## 4. 教师系统：CERLAB Autonomous Flight

### 4.1 系统概览

CERLAB Autonomous Flight 是一个经典机器人无人机自主飞行系统，由三个模块组成：

**感知模块**
- 传感器：RGB-D 相机、LiDAR / 点云、IMU、里程计
- 功能：动态障碍物跟踪、局部/全局地图构建、深度估计、碰撞风险估计

**规划模块**
- 算法：B 样条轨迹优化、增量式 PRM、类 MPC 规划
- 输出：未来轨迹 τ_t = {p_{t+1}, ..., p_{t+K}}（局部路径、未来路点）

**控制模块**
- 输出：速度 / 姿态指令 u_t = [vx, vy, vz, yaw_rate]
- 发布话题：`/CERLAB/quadcopter/cmd_vel`（geometry_msgs/TwistStamped）

### 4.2 用于蒸馏的教师输出

| 信号 | ROS 话题 | 作用 |
|---|---|---|
| 前视相机图像 | `/camera/color/image_raw` | 学生输入 |
| 教师轨迹 | `/dynamicNavigation/bspline_trajectory` | 规划层 KD 标签 |
| 教师控制 | `/autonomous_flight/target_state` | 控制层 KD 标签 |
| 位姿 / 里程计 | `/CERLAB/quadcopter/pose`, `/odom` | 同步参考基准 |

### 4.3 仿真环境

- 仿真器：**Gazebo 11**（ROS Noetic）
- 主要场景：`corridor_dynamic_9_nohuman`
- 教师系统通过 2D Nav Goal 输入实现全自主运行

## 5. 学生网络

### 5.1 设计原则

- **训练阶段：** 接收教师轨迹标签 + 控制标签作为监督
- **推理阶段：** 仅使用前视相机图像——不使用 LiDAR、地图、在线规划器，也不使用任何教师信号

### 5.2 网络结构

```
前视相机图像 I_t (480×640×3)
        │
        ▼
  MobileNetV2 Backbone
  （轻量 CNN 编码器，1280 维特征）
        │
        ▼
  策略头
  ├── 轨迹头 → τ_student = {(dx_1,dy_1,dz_1), ..., (dx_K,dy_K,dz_K)}
  └── 控制头 → u_student = [vx_b, vy_b, vz_b, yaw_rate]
```

- 控制头：MLP（1280 → 256 → 4）
- 时序建模（可选）：在图像序列上使用 RNN / TCN
- 输出坐标系：**机体系**（相对位置，而非世界系）

### 5.3 机体系的合理性

轨迹标签以无人机机体系（相对位移）表示。若使用世界系标签，学生可能会记住地图上的绝对位置，而不是学习基于视觉的导航行为。机体系标签能够在不同起始位置之间泛化。

相机系到机体系的映射关系：`x_c = -dy_b, y_c = -dz_b, z_c = dx_b`

```
Y_traj(t) = [[dx_1, dy_1, dz_1],

             ...
             [dx_K, dy_K, dz_K]]   (K=10，机体系相对坐标)
```

## 7. 蒸馏策略

**概览：** JointKD 是本研究提出的方法。BC、TrajKD、CtrlKD 是消融实验，分别隔离出各设计组件的贡献。

| 角色 | 方法 | 被移除的部分 |
|---|---|---|
| 无 KD 基线 | BC | 两种知识形式都被移除 |
| 消融 A | TrajKD | 仅保留规划知识；移除执行知识 |
| 消融 B | CtrlKD | 仅保留执行知识；移除规划知识 |
| **提出的方法** | **JointKD** | 完整方法 |

---

### 7.1 BC —— 无蒸馏基线

```
输入：   I_t
输出：   u_student = [vx_b, vy_b, vz_b, yaw_rate]
标签：   u_teacher（CERLAB 控制器输出，单步）
损失：   L_BC = MSE(u_student, u_teacher)
```

**作用：** 建立"纯动作模仿、不做任何 KD"的能力上限（ceiling）。不编码任何规划结构；在闭环部署中容易受分布偏移影响。

---

### 7.2 消融 A —— TrajKD（仅规划知识）

TrajKD 通过移除执行层监督，隔离出规划层 KD 的贡献。它采用**轨迹正则化 backbone**方案（Option B 架构）：轨迹头在训练阶段作为辅助项，部署时被丢弃，从而迫使 backbone 编码规划意图，而无需额外的几何控制器。

```
训练阶段：
  输入：   I_t
  Backbone → 轨迹头（辅助）+ 控制头（主）
  标签：   τ_teacher（K=10 个机体系路点）+ u_teacher（单步）
  损失：   L_traj_only = λ·L_traj + L_ctrl（L_ctrl 为单步 MSE，固定部署接口）

部署阶段：
  仅使用控制头 → 直接输出 cmd_vel
  轨迹头被丢弃
```

**设计说明：** 将轨迹头作为辅助项（而非部署输出）可以避免部署时需要额外的几何控制器（如 pure pursuit），使部署接口与 BC 保持一致。另一种实现方式（TrajKD+PP：轨迹作为输出 → pure pursuit → cmd_vel）仅作为参考记录，不纳入主实验序列。

**该消融回答的问题：** 在 backbone 上增加规划层监督（轨迹 KD）是否能比纯 BC 提升导航效果？

---

### 7.3 消融 B —— CtrlKD（仅执行知识）

CtrlKD 通过移除规划层监督，隔离出执行层 KD 的贡献。学生学习教师控制器在未来时域 H 上的时序执行模式。

```
输入：   I_t
输出：   U_student = [u_t, u_{t+1}, ..., u_{t+H}]
标签：   U_teacher（在 ctrl_body.csv 上滑窗取得）
损失：   L_ctrl_seq = Σ_k w_k · MSE(u_student(t+k), u_teacher(t+k))
```

**推理方式：** receding horizon —— 预测 H 步，只执行 u_t，下一时刻 t+1 重新预测。

**关键要求：** 标签必须来自 CERLAB 控制器的真实输出（`ctrl_body.csv`），而不是由轨迹做有限差分推导得到。控制器编码了动力学约束、跟踪误差反馈与惯性，这些是轨迹本身不具备的。

**数据：** 在已有的 `ctrl_body.csv` 上滑窗即可，无需新增数据采集。

**该消融回答的问题：** 蒸馏时序执行知识是否能比纯 BC 提升导航效果？

---

### 7.4 JointKD —— 提出的方法（规划 + 执行）

JointKD 同时结合两种知识形式。共享的 MobileNetV2 backbone 同时接收来自轨迹辅助损失和控制序列损失的梯度信号，学习到既编码规划意图又编码执行行为的视觉表征。

```
架构：
  前视相机图像 I_t
          ↓
    MobileNetV2 Backbone（共享）
          ├── 轨迹头  [仅训练使用，部署时丢弃]
          │     输出：K=10 个机体系路点 τ_student
          │     损失：L_traj = MSE(τ_student, τ_teacher)
          │     作用：将规划意图注入 backbone 表征
          └── 控制序列头  [部署使用]
                输出：[u_t, u_{t+1}, ..., u_{t+H}]
                损失：L_ctrl_seq = Σ_k w_k · MSE(u_pred(t+k), u_teacher(t+k))
                作用：蒸馏时序执行行为

联合损失：  L = λ_traj · L_traj + λ_ctrl · L_ctrl_seq
部署方式：  仅使用控制序列头；receding horizon 执行
```

**初始超参数：** λ_traj = 1.0，λ_ctrl = 1.0

**λ 消融范围：** λ_traj 与 λ_ctrl 均在 {0.1, 1.0, 5.0} 中扫描

**为什么轨迹头是辅助项而非部署输出：** 若部署轨迹头，需要额外的路点跟踪控制器，会使部署复杂化并引入新的失效模式。将其作为辅助监督，可以在保持与 BC、CtrlKD 相同部署接口的同时，达到同样的规划层 backbone 正则化效果。

**与 TCP（Wu et al., NeurIPS 2022）的区别：** TCP 是在人类真实驾驶数据上训练的多任务模仿学习。JointKD 是知识蒸馏——教师监督信号来自经典无人机自主飞行系统的输出，而非人类示范。TCP 部署时使用两个分支；JointKD 部署时仅使用控制头。

## 8. 评估方案

### 8.1 实验设计

所有实验使用完全相同的条件，以保证消融实验的公平性：
- 相同的仿真环境与航线
- 相同的学生 backbone（MobileNetV2）
- 部署阶段相同的"仅前视相机"输入
- 相同的数据划分（uav_kd_v001）

| 方法 | 角色 | 教师信号 | 部署输出 | 损失 |
|---|---|---|---|---|
| BC | 无 KD 基线 | u_t（单步） | cmd_vel（单步） | L_BC |
| TrajKD | 消融 A（仅规划） | τ_{t:t+K} + u_t | cmd_vel（单步） | λ·L_traj + L_ctrl |
| CtrlKD | 消融 B（仅执行） | U_{t:t+H}（控制器） | cmd_vel（receding horizon） | L_ctrl_seq |
| **JointKD** | **提出的方法** | τ_{t:t+K} + U_{t:t+H} | cmd_vel（receding horizon） | λ·L_traj + λ·L_ctrl_seq |

### 8.2 评估指标

**离线指标：**
| 指标 | 说明 |
|---|---|
| 控制 MSE | 分维度：vx、vy、vz、yaw_rate |
| 轨迹误差（ATE） | 平均轨迹误差 |
| 平滑度 | 控制 / 轨迹的平滑程度 |
| 模型大小 | 参数量（MB） |
| 推理 FPS | 每秒帧数 |

**Gazebo 部署指标：**
| 指标 | 说明 |
|---|---|
| 成功率（SR） | 任务完成的百分比 |
| 碰撞率（CR） | 发生碰撞的任务百分比 |
| 轨迹误差 | 相对于教师参考路径 |
| 完成时间 | 每次任务的平均耗时 |
| 实时 FPS | 实际推理速度 |

### 8.3 预期结果

**主假设：** JointKD 优于所有消融方法，验证规划层知识与执行层知识都是本方法不可或缺的组成部分。

**消融实验预期发现：**
- TrajKD > BC：规划层监督能在纯动作模仿之上提升 backbone 表征
- CtrlKD > BC：时序执行知识能提升单步 BC 的平滑度与一致性
- JointKD > TrajKD 且 JointKD > CtrlKD：两种知识形式各自独立贡献，二者结合具有互补效果

## 9. 相关工作

| 类别 | 代表工作 | 与本研究的关系 |
|---|---|---|
| 知识蒸馏 | Hinton KD；Teacher-Assistant KD | 基础：KD 范式与损失设计 |
| 规划器到策略 | PlanNetX；MPNet（Qureshi et al., IEEE T-RO 2020, arXiv:1907.06013）；MonoMPC | 以经典规划器输出作为神经策略的监督；MPNet 直接启发了 TrajKD 的"经典→神经"范式 |
| 运动规划器 + 策略蒸馏 | Liu et al.（PMLR 2022）—— 将运动规划器增强的策略蒸馏为视觉控制 | 概念上最接近的工作；应用于机械臂操作领域 |
| 轨迹引导的 BC / 多任务 IL | TCP（Wu et al., NeurIPS 2022, arXiv:2206.08129）；DBC —— 基于任务 KD 的驾驶行为克隆路线跟随（jizefeng0810, CARLA）；CILRS（Codevilla et al., 2019, arXiv:1904.08980） | TCP：在真实标签上训练的多任务 IL（非 KD），采用轨迹+控制双分支架构，为联合训练轨迹+控制（Option B / JointKD）提供架构参考；DBC：驾驶 BC 场景下"经典→神经"KD 范式，是 TrajKD+PP 的直接结构参考；CILRS：用辅助任务监督（速度预测）提升 BC backbone，启发了将轨迹作为辅助损失的思路 |
| 无人机 BC / 模仿学习 | SATMN；PPO+BC；LSTM-TD3+BC | 面向无人机导航与控制的 BC/IL 方法 |
| 经典无人机自主飞行系统（教师） | CERLAB B 样条轨迹优化；动态障碍物跟踪；隧道巡检；增量式 PRM | 教师系统的直接参考 |
| 无人机 + KD | 面向无人机的 FHE-aware KD（arXiv:2411.00403） | 无人机领域相关 KD 工作 |

**定位陈述：** 现有 KD 工作大多是神经网络到神经网络的蒸馏。现有无人机视觉策略依赖 BC/RL，不具备显式的规划知识。本研究处于 KD、规划器到策略、无人机视觉导航三者的交叉点——以经典自主飞行系统作为教师。

## 10. 预期贡献

1. **方法 —— JointKD：** 一种双层知识蒸馏方法，将规划层知识（轨迹）与执行层知识（控制序列）从经典无人机自主飞行系统迁移到轻量前视视觉策略。轨迹头在训练阶段作为辅助监督，将规划意图注入 backbone；控制序列头是部署时的输出。这是首个从非神经网络无人机教师中联合蒸馏结构化规划知识与执行知识、并迁移到轻量视觉学生的方法。

2. **数据集：** 一个同步的教师知识数据集，将前视相机观测与 CERLAB 规划器轨迹、控制器输出配对，在 Gazebo 中采集。支持对"以经典自主飞行系统为教师的 KD"进行可复现评估。

3. **消融实验：** 在相同条件下进行的受控消融实验（BC / TrajKD / CtrlKD / JointKD），验证两种知识形式各自独立贡献，且二者在 JointKD 中的结合能取得最佳的轻量导航性能。
