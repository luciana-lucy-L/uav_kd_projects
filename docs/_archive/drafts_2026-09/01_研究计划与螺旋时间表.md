## 第一部分：诊断问题（决定后续一切）

### 1.1 现象复述（来自项目已有记录）

| | 教师 | BC(v002) | TrajKD | SelfRedWP |
|---|---|---|---|---|
| yaw_rate std | **0.340** | 0.104 | 0.027 | 0.042 |
| frac(\|yr\|>0.15) | **17.7%** | 10.4% | 0.9% | 3.4% |

训练集转向帧占比 ~11.8%，验证集 ~11.4%。

### 1.2 关键观察

**BC 的转向"频率"（10.4%）几乎等于训练数据的转向帧占比（11.8%），但"幅度"只有教师的 30%。**
而 TrajKD / SelfRedWP 是频率和幅度**双双坍缩**。

→ 这不是单一机制能解释的。

### 1.3 三个候选机制

| 机制 | 描述 | 能解释 | 不能解释 |
|---|---|---|---|
| **M1 类别不平衡**（用户假设） | 转向样本仅 ~12%，未加权 MSE → 梯度被直飞样本主导 → 幅值低估 | BC 的"频率对、幅度小" | 为什么 TrajKD 更差 |
| **M2 标签多峰 / 目标不可观测** | 无目标输入，视觉相同的岔路帧对应左/右矛盾标签 → MSE 最优解 = 均值 ≈ 0 | 所有模型的整体压缩；闭环卡死 | 为什么 BC 频率还对 |
| **M3 辅助 loss 梯度干扰** | 轨迹 loss 主导共享 backbone，轨迹标签方差低（多为直飞）→ 抑制控制头输出方差 | TrajKD / SelfRedWP 比 BC 更差 | BC 自身的压缩 |

**结论：三者很可能同时存在，权重未知。** 必须先测量，不能先假设。

### 1.4 判别实验设计（R1 第一阶段，W1–W2）

全部使用**现有数据和现有已训练模型**，不采集任何新数据。

| 编号 | 实验 | 做什么 | 判读 | 成本 |
|---|---|---|---|---|
| **T1** | **训练集自身复现测试** | 在**训练集**上评估已训练模型的 yaw_rate std，与训练标签的 std 对比 | 训练集上也复现不了 → **不是数据量问题**（是拟合/多峰问题）；训练集能复现、验证集不能 → **是泛化问题，加数据有用** | 半天 |
| **T2** | **过拟合能力测试** | 取 200 个转向帧，关闭正则，让模型过拟合 | 拟合不了 → 输入-标签映射本身矛盾（M2）；能拟合 → 容量与优化没问题（指向 M1） | 半天 |
| **T3** | **损失加权 / 平衡采样**（**直接检验 M1，即用户假设**） | 不采新数据，把转向帧 loss 权重调高（或平衡采样），重训 BC | yr_std 显著回升 → **M1 成立，用户假设正确**，且白捡一个便宜方法；无变化 → M1 非主因 | 1 次训练（2–3 h） |
| **T4** | **近邻标签方差测试**（检验 M2） | 用 backbone 特征做跨 episode 最近邻检索，统计视觉近邻帧对的 yaw_rate 标签差异分布 | 视觉几乎相同但标签相反的比例高 → M2 成立，**加数据无用，必须加目标输入** | 半天 |
| **T5** | **辅助 loss 干扰测试**（检验 M3） | 把 TrajKD 的 λ_traj 降到 0.01 重训 | yr_std 回到 BC 水平 → M3 成立，是 loss 平衡问题而非方法问题 | 1 次训练 |

### 1.5 诊断结果 → 采集协议的映射

| 诊断结论 | 采集协议怎么改 | 后续影响 |
|---|---|---|
| M1 为主 | **刻意采集转向密集的 episode**（多设岔路目标点、S 形路线、往返掉头），目标转向帧占比提升到 30%+ | 数据量需求上升，采集周期延长 |
| M2 为主 | 目标点记录是**必须的**；数据量本身不是关键，覆盖度才是 | 采集量可以不大，但必须多目标点 |
| M3 为主 | 与采集无关，是 loss 权重设计问题 | 需在 R2 加入 λ 敏感性扫描 |
| 混合（最可能） | 三者都做：目标条件化 + 转向密集采集 + loss 平衡 | 按上面三条合并 |

⚠️ **不做 T1–T5 就直接采数据，是本项目最大的浪费风险。**

## 第二部分：项目重建的结构规划

现有代码是"每个方法一个训练脚本"（`train_bc.py` / `train_traj_kd.py` / `train_self_red_wp.py`）。
**本研究需要 5 臂 × 3 容量 = 15 个训练配置，这种结构会崩。**

### 2.1 必须的结构改造

| 模块 | 现状 | 目标 | 验收标准 |
|---|---|---|---|
| **训练入口** | 3 个独立脚本 | **单一 `train.py` + YAML 配置驱动** | 换臂/换容量只改 config，不改代码 |
| `kd_uav/models/backbone.py` | MobileNetV2 固定 | 支持 `width_mult` 参数，从头训练 | α=1.0/0.5/0.35 均可实例化 |
| `kd_uav/models/goal_encoder.py` | **不存在** | 相对目标向量 → MLP → embedding | 输出维度可配 |
| `kd_uav/models/temporal.py` | **不存在** | LSTM 时序融合 | 支持可变窗口长度 |
| `kd_uav/models/heads/` | 只有单步 control_head | control_head / control_seq_head(H步) / trajectory_head | 三种头可自由组合 |
| `kd_uav/models/policy.py` | **不存在** | 统一策略容器：backbone + goal + temporal + heads | 由 config 组装 |
| `kd_uav/losses/` | bc_loss, traj_kd_loss | + ctrl_kd_loss, joint_loss, feat_kd_loss(InfoNCE) | 每个 loss 单元测试通过 |
| `kd_uav/datasets/` | 单帧 | + 序列采样器、目标字段、平衡采样器 | 不跨 episode 边界 |
| `kd_uav/eval/` | **空** | eval_offline / eval_robustness / compute_metrics | 可批量跑全网格 |
| `kd_uav/diagnostics/` | **不存在** | T1–T5 的实验脚本 | R1 用 |
| `ros_ws/src/uav_kd_eval_tools/` | **空包** | 自动化部署评估：SR / CR / 轨迹误差 / 完成时间 + 批量运行 | 一条命令跑 N 次并出 CSV |

### 2.2 数据 schema 变更

新增字段（相对现有 `uav_kd_v002`）：

| 字段 | 内容 | 来源 |
|---|---|---|
| `goal_body` | 机体系下的相对目标向量 [dx, dy, dz] | 2D Nav Goal + odom 换算 |
| `goal_dir` | 归一化方向向量（Loquercio 式，备选） | 同上 |
| `goal_dist` | 到目标的距离 | 同上 |
| `episode_goal_id` | 本段使用的目标点编号 | 采集时记录 |
| `is_turning` | 是否转向帧（\|yr\|>阈值），用于平衡采样 | 离线计算 |
