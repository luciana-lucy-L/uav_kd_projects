## 2. 逐篇论文分析

### 2.1 Loquercio et al. 2021 — *Learning High-Speed Flight in the Wild*

**出处**：Science Robotics 6(59), 2021 · [arXiv:2110.05113](https://arxiv.org/abs/2110.05113) · [Science](https://www.science.org/doi/10.1126/scirobotics.abg5810) · 本地：`02 Learning High-Speed Flight in the Wild.pdf`

#### 核心事实 ✅（我抓取了 ar5iv 全文页）

| 组件 | 内容 |
|---|---|
| **教师** | **采样式运动规划器（Metropolis-Hastings 采样）**，特权信息 = "完整的平台状态知识 + 环境的完整 3D 地图 / 点云"，且**无计算预算限制** |
| 教师输出 | 从 P(τ\|τ_ref, C) 采样碰撞-free 轨迹；轨迹表示为 3 控制点三次 B 样条；选**代价最低的 3 条**作为训练标签 |
| **学生输入** | 深度图 640×480（SGM 立体匹配）+ 平台速度 ℝ³ + 姿态（9维旋转矩阵）+ **期望飞行方向**（指向 1 秒后参考点的归一化向量） |
| **学生输出** | **M=3 条候选轨迹**（各 10 个位置 / 1 秒）+ 每条的碰撞代价估计 |
| 学生骨干 | **预训练 MobileNet-V3** |
| **损失** | Relaxed Winner-Takes-All (R-WTA) + 碰撞代价回归：`L = λ₁·R-WTA(T_e, T_n) + λ₂·Σ‖c_k − C_collision(τ_nk)‖²` |
| **训练策略** | **DAgger**：滚动学生策略 → 用教师标注学生访问到的状态；每 30 个环境放宽跟踪阈值；共约 **90K 样本** |
| 目标指定 | 用户或上层规划器给一条**不需碰撞-free 的参考轨迹**，网络每步用"指向 1 秒后参考点的归一化向量" |
| 训练/测试 | 纯仿真训练 + 零样本迁移到真实森林、雪地、废弃火车、坍塌建筑 |

#### 与你的重叠面 🔶

| 维度 | 重叠程度 |
|---|---|
| **教师是经典规划器** | 🔴 **完全重叠**。你 `research.md` §2.1 声称的"教师不是神经网络，是经典自主流水线"——这里已经做过，而且是 Science Robotics |
| **蒸馏轨迹（规划层知识）到 UAV 视觉策略** | 🔴 **完全重叠**。这正是你的 TrajKD |
| 轻量 MobileNet 学生 | 🔴 重叠（他们 MobileNet-V3，你 MobileNetV2） |
| 四旋翼避障任务 | 🔴 重叠 |
| 单目 RGB 输入 | 🟢 **不重叠**——他们用深度图 |
| 蒸馏"执行层"（控制序列） | 🟢 **不重叠**——他们完全不蒸馏控制器，轨迹交给一个独立的跟踪控制器执行 |
| 教师内部分层的对照实验 | 🟢 **不重叠**——他们只蒸馏一层，没有"蒸馏哪一层更好"的问题 |

#### 对你的具体威胁 🔶

1. **你 `research.md` §2.1 的表格（"本研究：经典 UAV 自主栈 → 轻量视觉策略"）作为 novelty 主张，已经失效。** 必须改写。
2. **§10 贡献 1 中"首个从非神经无人机教师联合蒸馏结构化规划与执行知识"这句，"首个"里只有"联合（规划+执行）"这半句还有救**，"从非神经教师蒸馏"这半句站不住。
3. 你的"轻量化"卖点也被覆盖（同一骨干家族）。

#### 你能从它这里拿走什么（这才是最有价值的部分）✅→🔶

| 他们的做法 | 对你的意义 |
|---|---|
| **R-WTA 多假设输出（M=3 条轨迹）** | 这是对"标签多峰 → MSE 回归到均值"的**标准解法**。你三个模型 yaw_rate 坍缩，正是这个病。他们的存在本身就是这个诊断的旁证 |
| **DAgger 数据聚合（教师在线标注学生访问的状态）** | 你的教师**跑在同一个 Gazebo 里，随时可调用**——DAgger 对你几乎是免费的。这同时回答了你上一轮的"采集成本高"顾虑：DAgger 是自动化标注，不需要人 |
| **方向向量作为目标输入** | 第二个"廉价目标指定"的存在证明：不需要 3D 地图，只要一个方向向量 |
| 纯仿真训练 + 传感器噪声模拟 | 说明"仿真-only"不是原罪，但他们靠大规模环境随机化撑起了泛化，你没有这个体量 |

### 2.2 Li & Zhao 2026 — *Omni-View and Cross-Modality KD for Mobile Robots*

**出处**：[arXiv:2603.20679](https://arxiv.org/abs/2603.20679)，2026-03-21，cs.RO · 本地：`01 Enhancing Vision-Based Policies...`

#### 核心事实 ✅（我抓取了 HTML 全文）

| 组件 | 内容 |
|---|---|
| **教师** | **RL 策略（SAC，5M 环境步）**，输入 = 全向深度图（用 DepthAnythingV2 把 4 路 RGB 转深度后拼接）→ **不是经典规划器，是学习得到的黑箱** |
| **学生** | 单目 RGB → ResNet 编码器 → 与 **goal embedding** 拼接 → **LSTM 时序融合** → MLP 输出动作 |
| **目标指定** | **机器人局部坐标系下的 2D 目标点**，MLP 编码后与图像特征拼接；支持静态目标和按预定策略移动的目标 |
| **损失** | `L_s = λ₀·L_act + λ₁·L_con`；L_act = 学生/专家动作 L2；**L_con = InfoNCE 对比损失**，对齐师生 embedding，正样本对 = 全局位姿上空间接近的状态；λ₁ 从 0.9 线性衰减到 0.1 |
| 平台 | 地面**全向移动机器人**，板载 NVIDIA Jetson Orin NX（25W） |
| 环境 | ROS Gazebo，**4m × 4m** 场景 |
| 数据 | 50,000 组 (state, image, action)，来自 4 个仿真环境 + 1 个真实实验室 |
| 评估 | 80 次仿真（4 场景 × 20）+ 20 次真机；指标 = Action Error / Success Rate（0.3m 内无碰撞）/ Moving Distance / 板载推理延迟 |
| 结果 | **72% SR**，对比 MAE 50%、单视角 RGB 基线 40% |
| 基线 | ResNet18/50 各模态变体、DINOv2 / CLIP / MAE / MultiMAE、RoboSaGA、VISARL、Zhang et al. 跨模态方法 |
| 代码 | 摘要称 "Code will be released publicly"（**需你确认是否已放出**） |

#### 与你的重叠面 🔶

| 维度 | 重叠程度 |
|---|---|
| **动机叙事** | 🔴 **几乎逐字重合**："可迁移性 / 板载算力 / 传感器硬件成本 三难" = 你的降本故事 |
| **系统结构** | 🔴 完全重叠：信息丰富教师 → 轻量单目 RGB 学生 |
| **核心命题** | 🔴 **命题形状完全重合**："蒸馏动作以外的东西 > 只模仿动作"。这正是 JointKD 要证的 |
| 仿真器 | 🔴 同为 ROS Gazebo（不重要，但会被注意到） |
| 评估指标 | 🔴 SR / 碰撞 / 延迟，与你计划的一致 |
| **教师本质** | 🟢 **不重叠**：他们是 RL 黑箱，你是可分解的经典模块栈 |
| **蒸馏的知识类型** | 🟢 **不重叠**：他们对齐 latent（无语义），你蒸馏结构化中间输出（τ、U，有语义） |
| 平台 | 🟢 不重叠：地面 2D 4m×4m vs 空中 3D 走廊 |
| 学生架构 | 🔴 他们有 goal + LSTM，**你没有——这是你的缺陷不是差异** |
| 真机验证 | 🔴 他们有，你没有 |

#### 对你的具体威胁 🔶

1. **JointKD 的核心命题被提前证明了**，而且有真机。你再证一遍边际价值 ≈ 0。
2. **动机段落几乎撞车**——如果你的 Introduction 写"轻量机器人面临传感器成本与算力限制"，读者会立刻想到这篇。
3. 你在部署证据上永远处于下风（仿真 vs 真机）。

#### 关键洞察：为什么他们**必须**用 latent 对齐 🔶

他们的教师是一个 RL 黑箱，内部**没有**"规划层""执行层"之分。教师身上可提取的知识只有两样：动作，和中间 embedding。用 InfoNCE 对齐 latent **不是设计偏好，是被教师结构逼出来的唯一选择**。

而你的教师是模块化的，中间产物（B样条轨迹、控制序列）是人类可解释的、有物理语义的。**这让你能问一个他们结构上问不出来的问题。**（见 §4.3）

#### 你能从它这里拿走什么

| 他们的做法 | 对你的意义 |
|---|---|
| **相对 2D 目标点 + MLP 编码** | 廉价目标指定的**第一个存在证明**，只需里程计，不需 3D 地图。你的 `traj_body` 已经是机体系相对坐标，改造成本极小 |
| **LSTM 时序融合** | 直接补上你"单帧无记忆"的缺陷 |
| **InfoNCE latent 对齐** | 可作为你消融表里的一行基线（代表"表征层蒸馏"） |
| 他们的基线集合 | DINOv2/CLIP/MAE 这些预训练编码器对比，可以直接借鉴设计 |

### 2.4 Wu et al. 2022 — *TCP (Trajectory-guided Control Prediction)*

**出处**：NeurIPS 2022 · [arXiv:2206.08129](https://arxiv.org/abs/2206.08129)

#### 核心事实 ✅（摘要原文）

> "our integrated approach has two branches for trajectory planning and direct control... The trajectory branch predicts the future trajectory, while the **control branch involves a novel multi-step prediction scheme** such that the relationship between current actions and future states can be reasoned. **The two branches are connected so that the control branch receives corresponding guidance from the trajectory branch at each time step.** The outputs from two branches are then fused..."

- ✅ 基准：CARLA Leaderboard
- ⚠️ 监督信号来源（人类驾驶真值 vs 专家）与融合机制细节，摘要未说明，需查正文

#### 与你的重叠面 🔴 **这是对 JointKD 最直接的威胁**

| 你的 JointKD | TCP |
|---|---|
| 轨迹头（辅助）+ H 步控制序列头 | 轨迹分支 + **多步预测**控制分支 |
| 共享 backbone | 共享 backbone |
| 两个 loss 加权 | 两分支**相互连接**（比你还多一层耦合） |
| 部署丢弃轨迹头 | 部署融合两分支 |

**你的 JointKD ≈ TCP 减去分支间连接和融合。** 也就是说，在架构层面你不是"提出"，而是"简化"。你 `research.md` §7.4 里写的两点区分（"TCP 是 IL 不是 KD""TCP 部署两个头"）：

### 2.7 Visual Teach & Repeat (VT&R) 系列

**出处**：
- [Clement et al., *Monocular VT&R Aided by Local Ground Planarity* (arXiv:1707.08989)](https://arxiv.org/abs/1707.08989)（另见 J. Field Robotics 2017）
- [Warren et al., *Towards VT&R for GPS-Denied Flight of a Fixed-Wing UAV* (FSR 2017)](https://www.dynsyslab.org/wp-content/papercite-data/pdf/warren-fsr17.pdf)
- [*UAV See, UGV Do* (arXiv:2505.16912)](https://arxiv.org/abs/2505.16912)（2025）

#### 核心事实 ⚠️（来自搜索摘要，未读正文）

- VT&R = teach 阶段（人工或规划器驾驶，沿途采图）+ repeat 阶段（仅用相机重复该路线），**不需要 GPS、不需要全局度量地图**
- 单目实现可达公里级路线、厘米级精度（借助地面平面假设恢复尺度）

#### 与你的重叠面 🔴 **这是对你"应用场景"的威胁，不是对方法的威胁**

你描述的商业场景——"经典无人机先飞一圈，之后轻量无人机重复送货"——**逐字就是 VT&R 的定义**。

#### 你必须能回答的问题 🔶

> "VT&R 用几何方法早就能做路线重复，为什么要换成神经网络？"

可能的答案（需你选一个并用实验支撑）：
1. **动态障碍物**：VT&R 重复固定路线，遇到临时障碍（叉车、行人、堆放的货物）需要额外的避障模块；你的教师 CERLAB 本身就带动态障碍处理，学生可以继承这个能力 ← 🔶 **我认为这是你最强的答案，而且你的 world 就叫 `corridor_dynamic_9`**
2. 外观变化鲁棒性（光照/季节）
3. 路线泛化（不只重复原路线）

**如果选 1，你的实验设计必须包含动态障碍场景，且必须和"VT&R 式的固定路线重放"做对比。** 这是一个具体的、可执行的实验要求。

### 2.8 目标指定 / 导航基础模型系列

**出处**：
- [ViNG: Learning Open-World Navigation with Visual Goals](https://www.semanticscholar.org/paper/ViNG:-Learning-Open-World-Navigation-with-Visual-Shah-Eysenbach/0fd47bf484a05001ce787747cf5a879b9202ebfa)
- [GNM: A General Navigation Model (arXiv:2210.03370)](https://arxiv.org/abs/2210.03370)
- [NoMaD: Goal Masked Diffusion Policies (arXiv:2310.07896)](https://arxiv.org/abs/2310.07896)
- [代码库 visualnav-transformer](https://github.com/robodhruv/visualnav-transformer)
- [SIGN: Safety-Aware Image-Goal Navigation for Autonomous Drones (arXiv:2508.12394)](https://arxiv.org/abs/2508.12394)（2025）
- [Warehouse MAV vision-based line following (arXiv:2310.00950)](https://arxiv.org/abs/2310.00950)

#### 核心事实 ⚠️（搜索摘要级）

- ViNG：图像目标 + **非参数拓扑记忆**（图像图谱），不建度量地图
- GNM / ViNT / NoMaD：跨机器人形态的目标条件导航**基础模型**，零样本控制多种机器人
- SIGN：无人机图像目标导航 + 碰撞预测器的动作修正

#### 对你的两个不同影响 🔶

## 4. 幸存空间分析：你到底还能支撑什么

### 4.1 已死的三句话（必须从 research.md 删除或改写）

1. ❌ "现有 KD 工作大多是 NN→NN" —— 机器人领域根本不是（Lee 2020、LBC 2019、Loquercio 2021）
2. ❌ "现有无人机视觉策略依赖 BC/RL，不具备显式规划知识" —— Loquercio 明确蒸馏规划器轨迹
3. ❌ "本研究处于 KD、planner-to-policy、UAV 视觉导航三者的未探索交叉点" —— 该交叉点有 Science Robotics 论文占位

### 4.2 灰色地带（能说，但措辞要精确）

| 说法 | 允许的措辞 | 禁止的措辞 |
|---|---|---|
| 单目 RGB | "与依赖深度感知的既有工作不同，我们研究**仅用单目 RGB** 的可行边界" | "首个单目方案" |

| 场景 | "动态障碍走廊 + 3D 机动" | "首个在动态环境" |

### 4.3 真正的空白：**可分解教师的知识层级研究** ✅ 我认为这是唯一撑得住的核心

**研究问题**：

> 当教师是一个**可分解的经典自主栈**时，它内部的哪一层知识最值得蒸馏给单目视觉学生？
> 规划层（轨迹 τ）／执行层（控制序列 U）／表征层（latent 对齐）／动作层（BC）？

**为什么只有你能问这个问题**：
- Li & Zhao 的 RL 教师是黑箱，没有"规划层"可摘 → 他们只能做 latent 对齐
- Loquercio 的教师只输出轨迹，没有可蒸馏的控制器层 → 他们只能蒸馏一层
- LBC 的特权教师是神经网络 → 同样无分层
- **你的 CERLAB 教师同时暴露 τ 和 U，而且两者由不同物理模块产生，语义清晰**

**这把"经典教师"从劣势（老土、被占位）转成研究工具（唯一可分解的教师）。**

**完整对照组设计**（统一学生架构、统一数据、统一评估）：

```
统一底座： 单目RGB → encoder → +goal embedding → LSTM → head
           （goal + LSTM 借鉴 Li & Zhao 2026）

Arm 0  Teacher      教师自身性能上界（参考线）
Arm 1  BC           只蒸馏动作 u_t                      ← 已有
Arm 2  FeatKD       latent 对齐 (InfoNCE)               ← 复现 Li & Zhao，作为基线
Arm 3  TrajKD       规划层：轨迹 τ (K=10)               ← 已有，需在新底座上重跑
Arm 4  CtrlKD       执行层：控制序列 U (H步)            ← 待实现
Arm 5  JointKD      τ + U                              ← 待实现
Arm 6  All          τ + U + latent                     ← 可选
```

**输出的是一张表和一个结论**，不是一个新 loss。

### 4.4 第二块空白：**可蒸馏性边界（负结果导向）**

**研究问题**：教师的哪些决策**原理上无法**蒸馏给单目学生？

你已有的证据其实已经指向一个可论证的命题：
- 教师的转弯决策依赖 **深度 + 局部地图 + 目标方向**
- 单帧单目 RGB **不包含**目标方向，**不可靠地包含**深度
- → 在标签层面表现为多峰 → MSE 回归坍缩 → yaw_rate std 只有教师 8~30%

**这个链条如果用受控实验补齐（逐个恢复信息通道，看 yaw_rate std 如何回升），本身就是一个有信息量的结论。**

建议的信息通道消融：

| 配置 | 恢复的信息 | 预期 |
|---|---|---|
| 单帧 RGB（现状） | — | yr_std ≈ 0.10（已测） |
| + 目标方向向量 | 目标 | 多峰性大幅下降 |
| + LSTM 时序 | 历史/速度 | 恢复动态信息 |
| + 深度估计辅助任务 | 几何 | 补偿单目缺陷 |
| + 多假设输出 (R-WTA) | 多峰建模 | 剩余多峰性 |
| 教师（深度+地图+目标） | 全部 | yr_std = 0.34（已测） |

**这张表把"我们失败了"变成"我们量化了每个信息通道的贡献"。** 🔶 我认为这是你现有资产（已有的失败数据 + 可运行的教师）价值最高的用法。
